# ADR-0028: Sample demo keys, generation and demo clock

- Status: Decided
- Date: 2026-11-13
- Source: `add-sample-package` design.md Q11, Q13, Q22

## Context

PDR-0069 commits a demo signing key pair, an untrusted pair and ten demo keys, checked on every
change and regenerated by one command, plus a picker and a demo date. The library's public API
can create key pairs (`SigningKeyPair`) and issue keys (`LicenseIssuer`); `NotSupported` needs a
newer-format key that only the library's internal test seam writes. ADR-0005 uses an explicit
xUnit generator for the library's own examples.

## Decision

- **Key pairs** created once by an explicit generator test with `SigningKeyPair`, committed in
  `samples/demo-signing-keys/` as PEM and public lines, each file starting with the warning.
  Outside the package project, so no build output holds a private key. The demo public key is a
  constant in the product's code, as a vendor would ship it.
- **`Demo/demo-keys.json`** embedded in the package: per entry name, description, key (null for
  No key), optional demo date, and expected state, product, expiry and features.
- **Generator**: explicit xUnit test, run with
  `dotnet run --project samples/Acme.ContactForm.Tests -- -explicit only -method "*DemoKeyGenerator*" -showLiveOutput`.
  Fixed issue clock; fixed expiries (small plan 2099-12-31T23:59:59Z, expiring soon
  2030-01-31T23:59:59Z with demo date 2030-01-17T12:00:00Z, expired 2026-01-31T23:59:59Z). The
  edited key replaces one character of the full-plan key's signature part with a fixed other
  character. The damaged key is a fixed non-key string. Random key parts mean identifiers change
  on regeneration; the committed file is the source of truth.
- **Always-on tests** evaluate every entry against its expectations.
- **No `NotSupported` key**; no `InternalsVisibleTo` from the library to the sample.
- **Picker**: a singleton selection; a key source that decorates the configured one when the
  demo setting is on. Nothing writes configuration.
- **Demo clock**: a `TimeProvider` returning the chosen entry's demo date, or the system clock;
  given to the evaluator and the expiring-soon check only, not to the submission count.

## Alternatives Considered

| Option | Why not |
|---|---|
| Reuse the library's example keys `Nb_sm4Fxh5c` | ADR-0005 says never trust it in a product; the sample would teach the opposite |
| Generate keys with the vendor tool | Not scriptable yet (FR-22); its records add nothing to the sample |
| Node script generator | Would reimplement issuing outside the library |
| `InternalsVisibleTo` for a `NotSupported` key | Couples the sample to library internals; the sample must show public-API use only |
| Hand-crafted `NotSupported` bytes | Copies the internal format into the sample |
| Demo date via the system clock or a setting | Affects the whole site; a per-entry clock is scoped to the demo |

## Consequences

- A format change during the beta needs one regeneration and a commit.
- Seven of eight states are visible in the demo; `NotSupported` only in tests.

## Reversal Cost

Low. The keys file and generator are sample-only; a `NotSupported` entry can be added if the
library gains a public way to write one.
