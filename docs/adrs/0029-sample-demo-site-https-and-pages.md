# ADR-0029: Sample demo site served over HTTPS, with Home and Contact pages

- Status: Decided
- Date: 2026-11-16
- Source: `add-sample-package` design.md Q27 (from Q25, Q26)

## Context

PDR-0072 serves the demo site at a secure local address with one documented setup step,
trusting the local development certificate, and the plain address forwarding. Carl's run of
task 10.1 found the backoffice sign-in refused at the plain address: Umbraco 17's backoffice
uses OpenIddict, which rejects non-HTTPS requests (ID2083). PDR-0073 adds Home and Contact
pages in one plain layout with editable text. The site was started by `dotnet run` on the
template's `http` launch profile, and `DemoContentSeeder` created one `home` type, template and
page holding only the form. The demo must stay cross-platform and add no dependency.

## Decision

- **HTTPS with the .NET development certificate.** An `https` launch profile, first in
  `launchSettings.json`, serves `https://localhost:44365` and `http://localhost:15329`.
  `run-demo.mjs` starts the site with `--launch-profile https`. The `http`-only profile is
  removed.
- **Trust step**: `dotnet dev-certs https --trust`, documented in the sample README.
  `run-demo.mjs` runs `dotnet dev-certs https --check --trust` before starting; when it fails, it
  prints the trust command and starts the site anyway.
- **Forwarding**: `app.UseHttpsRedirection()` before `app.UseUmbraco()` in `Program.cs` (307 to
  the same path on the https port).
- **No security setting relaxed**: OpenIddict's transport security requirement and Umbraco's
  settings stay at their defaults.
- **Client generator** reads the OpenAPI document from the https address.
- **Pages**: `DemoContentSeeder` creates document types `home` (site name, heading, intro,
  footer text; root; child `contact`) and `contact` (heading, intro) on built-in Textstring and
  Textarea data types, templates from committed views, and the published Home and Contact
  pages, all with fixed keys. A plain Razor layout `Views/_Layout.cshtml` renders the header
  (site name; links to the root and its children by page name) and footer from the root's
  content. One stylesheet, `wwwroot/css/site.css`, neutral only.
- **Earlier data** is not migrated: the seeder logs a warning naming `umbraco/Data` when the old
  `home` type lacks the new fields.

## Alternatives Considered

| Option | Why not |
|---|---|
| Keep HTTP and disable OpenIddict's transport security requirement | Rejected by PDR-0072; a security relaxation a vendor could copy into a real site |
| `mkcert` or a certificate generated by `run-demo.mjs` | A new tool or dependency; still needs a trust step, which differs per operating system |
| Serve HTTPS only | The plain address would fail with no hint; PDR-0072 requires forwarding |
| `run-demo.mjs` refuses to start when the certificate is untrusted | Blocks Linux, where the check can fail after the trust step |
| Umbraco templates with a master template instead of a Razor layout | A third template to seed and keep in step; a Razor layout is the plainer pattern to copy |
| Block List or rich text for page content | More to seed and strip; plain text fields are enough for a demo |
| Migrate an earlier demo database | Code for a one-off; deleting local demo data is cheap |

## Consequences

- A developer trusts the development certificate once; on Linux some browsers may still warn,
  which the README explains with Microsoft's Linux guidance (accepted risk).
- Every documented demo address, including Swagger and the client generator, moves to
  `https://localhost:44365`.
- `run-demo.test.mjs` covers the start arguments and the certificate message.
- A working copy with old demo data deletes `umbraco/Data` once.

## Reversal Cost

Low. Launch profile, one middleware line, a check in `run-demo.mjs`, and sample-only seeder and
views.
